# Memory Index

- [Don't run tests yourself](feedback_test_running.md) — never invoke pnpm test, vitest, or rspec; let the user run their own tests
- [Keep PR comments brief](feedback_pr_comments.md) — default to 2-3 sentences for PR comments and review replies
- [Discuss design in prose](feedback_design_discussion.md) — for nuanced design trade-offs, use prose not AskUserQuestion modals
- [Don't edit PRs directly](feedback_pr_direct_edits.md) — draft PR descriptions/comments as text for Lily to paste, never call update_pull_request unasked
- [PR description style](feedback_pr_descriptions.md) — bullets not prose, delete non-applicable template sections, terse Testing Done, /task as linked ticket key
- [One-line comments only](feedback_comments.md) — never wrap explanatory comments across multiple lines, even for WHY comments
- [Warmer PR comment tone](feedback_comment_tone.md) — avoid a harsh or snarky tone in drafted PR and review comments; no em dashes
- [Results page for recommended changes](feedback_results_page.md) — reviews and design planning: deliver a local HTML page (Keep/Skip or Pick A/B/C cards, comments, Copy prompt), not chat-only
